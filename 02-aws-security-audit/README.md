# Cloud Security Misconfiguration Audit – AWS Environment Hardening

> Automated cloud security audit tool that detects misconfigurations in AWS using
> Python + Boto3, maps findings to **CIS AWS Benchmark** and **NIST CSF** controls,
> and generates a professional executive security report.

**Category:** Cloud Security / AWS / Vulnerability Assessment
**Author:** Kuldeep J. Jotaniya — MSc Cyber Security, Ravensbourne University (2025)

---

## 🎯 Objective

Build a practical Cloud Security Posture Management (CSPM) tool that scans an AWS
account for common misconfigurations, maps each finding to industry frameworks,
and produces an executive-level report — demonstrating cloud security skills
valued in SOC and cloud security roles.

## ✨ Features

- **15 automated checks** across IAM, S3, EC2 and CloudTrail (see table below).
- **Framework mapping** — every finding is tagged with its CIS AWS Benchmark and
  NIST 800-53 control reference.
- **Risk scoring** — a 0–100 posture score driven by weighted severities.
- **Two output formats** — machine-readable JSON and a self-contained HTML
  executive report.
- **Demo mode** — run the full pipeline with `--demo` and **no AWS account**,
  using bundled sample findings from an intentionally misconfigured lab.
- **CI-friendly** — exits non-zero when Critical/High findings are present.
- **Read-only** — only calls AWS `get`/`list`/`describe`/`generate` APIs; it
  never modifies your account.

## 🚀 Usage

```bash
pip install -r requirements.txt

# Portfolio demo — no AWS account required:
python audit.py --demo

# Live audit against a real account (read-only):
aws configure --profile my-lab          # or export AWS_* env vars
python audit.py --profile my-lab --region eu-west-2
```

Outputs are written to `findings/audit_findings.json` and
`reports/audit_report.html`.

## 🔍 Checks Implemented

| ID | Check | Service | Severity | CIS | NIST |
|----|-------|---------|----------|-----|------|
| IAM-001 | Root account MFA not enabled | IAM | Critical | 1.5 | AC-2 |
| IAM-002 | IAM user with administrator privileges | IAM | High | 1.16 | AC-6 |
| IAM-003 | Access key not rotated in 90 days | IAM | Medium | 1.14 | IA-5 |
| IAM-004 | Console user without MFA | IAM | High | 1.10 | IA-2 |
| IAM-005 | Weak IAM password policy | IAM | Medium | 1.8 | IA-5 |
| S3-001 | S3 bucket publicly accessible | S3 | Critical | 2.1.5 | SC-7 |
| S3-002 | S3 bucket logging not enabled | S3 | Medium | 2.1.2 | AU-2 |
| S3-003 | S3 default encryption not enabled | S3 | Medium | 2.1.1 | SC-28 |
| S3-004 | S3 bucket versioning disabled | S3 | Low | 2.1.4 | CP-9 |
| EC2-001 | Security group allows unrestricted sensitive port | EC2 | High | 5.2 | SC-7 |
| EC2-002 | EBS encryption by default disabled | EC2 | Medium | 2.2.1 | SC-28 |
| EC2-003 | Default security group allows inbound traffic | EC2 | Low | 5.4 | SC-7 |
| CT-001 | CloudTrail not enabled in all regions | CloudTrail | High | 3.1 | AU-12 |
| CT-002 | CloudTrail log file validation disabled | CloudTrail | Medium | 3.2 | AU-9 |
| CT-003 | CloudTrail logs not encrypted with KMS CMK | CloudTrail | Low | 3.7 | SC-28 |

EC2-001 expands across SSH, RDP, MySQL, PostgreSQL, Redis, MongoDB and
Elasticsearch ports, so a typical environment surfaces well over 20 distinct
finding instances.

## 📊 Sample Report

`reports/sample_audit_report.html` is generated by `python audit.py --demo`.
It opens in any browser and includes the risk score, severity breakdown, a full
findings table with remediation, and a framework coverage matrix.
